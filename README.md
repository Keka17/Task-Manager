# Real-Time Task Manager с интеграцией WebSocket <img width="90" height="84" alt="images (1)-Photoroom (1)" src="https://github.com/user-attachments/assets/2b070f18-4052-42c6-9aca-18076b42c685" />
Диспетчер задач в реальном времени, построенный на FastAPI. Проект включает многоуровневую систему безопасности, включая верификацию email и JWT-аутентификацию, фоновые задачи Celery, уведомления на почту через SMTP-сервер, локализацию (in18) и поддержку WebSocket для мгновенного обновления данных. 


## Основной функционал
* __Управление задачами (Secure CRUD)__:
   * Полный цикл операций, где __все эндпоинты защищены__ (Protected resource).
   * Ограничение доступа: Пользователь может взаимодействовать только с собственными задачами.
* __Асинхронность__: Полностью асинхронный стек (FastAPI, SQLAlchemy, Asyncpg, Celery, FastAPI-Mail, Pytest-Asyncio) для высокой производительности.
* __Real-time обновление__: Использование __WebSocket__ для мгновенного изменения статуса задач без перезагрузки страницы.
* __Верификация аккаунтов__: Двухэтапная регистрация с подтверждением email для предотвращения создания фиктивных аккаунтов.
* __Контроль доступа__: Неверифицированные аккаунты имеют ограниченный доступ и подлежат автоматическому удалению по истечении заданного времени.
* __Надежная аутентификация__:
   * __JWT Auth (Access + Refresh)__:
     * __Access Token__: Хранится в куках; атрибуты `httponly`, `secure` и `samesite` обеспечивают безопасность, защищая токен от кражи через XSS-скрипты и предотвращая его использование в CSRF-атаках.
     * __Refresh Token__: Передается в кастомном заголовке `x-refresh-token` для генерации новой пары токенов.
   * __Refresh Token Rotation__: При каждом обновлении пары токенов старый Refresh-токен становится недействительным.
   * __Blacklist__: Использованные или отозванные (при выходе из системы) Refresh-токены сохраняются в базе данных как "протухшие", что предотвращает их повторное использование. 

    
## Стек технологий
* Backend: _FastAPI, Uvicorn, Pydantic v2, Babel, WebSockets_
* Frontend: _JavaScript, CSS, HTML_
* Database: _PostgreSQL, SQLAlchemy, Alembic_
* Broker: _Redis_
* Tasks: _Celery, Celery Beat_
* Security: _JWT (PyJWT), Passlib (bcrypt), Cryptography, ItsDangerous_
* Templates: _Jinja2_
* Logging: _Loguru_
* Testing: _Pytest, Pytest-Asyncio_
* DevOps: _Docker, Docker Compose_

### Директории и файлы
* `app`: Верхний уровень, содержит основной код приложения.
    * `api`: Слой интерфейса приложения.
      * `endpoints`: API-эндпоинты (роуты) для обработки HTTP-запросов.
      * `schemas`: Pydantic-схемы для валидации и сериализации данных.
      * `websocket_board`: контроллер WebSocket-соединений.
    * `core`: Cодержит глобальные настройки конфигурации (Pydantic settings), настройки безопасности (JWT), конфигурацию шаблонизатора (Jinja2) и менеджер активных WebSocket-соединений.
    * `db`: Файлы миграций Alembic, конфигурация асинхронного подключения к базе данных, классы моделей SQLAlchemy.
    * `dependencies`: Зависимости (Dependencies) для проверки JWT-токенов и прав доступа путем извлечения текущего пользователя из HTTP-кук и WebSocket-соединений.
    * `exceptions`: Классы кастомных user-friendly исключений.
    * `handlers`: Перехват ошибок (например, 404, 500) и возврат структурированных JSON-ответов.
    * `locales`: Исходные тексты переводов (`.po`) и их бинарные копии (`.mo`). 
    * `middlewares`: Промежуточное ПО для логирования запросов и ответов.
    * `services`: Бизнес-логика приложения: CRUD-операции, взаимодействие с БД, отправка писем.
    * `static`: Cтатические файлы (изображения, js-скрипты, css-классы).
    * `tasks`: Конфигурация Celery и Celery Beat, реализация фоновых процессов (рассылка писем, удаление неверифицированных аккаунтов и аннулированных токенов из базы данных).
    * `templates`: HTML-шаблоны для писем, веб-страниц и доски с задачами.
    * `utils`: Файл конфигурации и логики для асинхронной отправки email-уведомлений.
    * `main.py`: Корень проекта для запуска FastAPI-приложения.
* `logs`: Файлы с логами разных уровней (INFO, WARNING, ERROR).
* `tests`: Тесты эндпоинтов, фикстуры и вспомогательные функции.
* `.dockerignore`: Список файлов и директорий, игнорируемых при сборке Docker-контейнера.
* `.gitignore`: Список файлов и директорий, игнорируемых системой контроля версий.
* `.env`: Хранение конфиденциальной информации (напр.,пароли баз данных и почты).
* `env.docker`: Хранение переменных окружения для Docker-контейнеризации.
* `alembic.ini`: Конфигурационный файл инструмента миграции баз данных Alembic.
* `babel.cfg`: Конфигурационный файл для извлечения строк локализации.
* `docker-compose.yaml`: Файл Docker Compose, содержащий инструкции, необходимые для запуска и настройки сервисов.
* `Dockerfile`: Набор инструкций для автоматической сборки образа Docker.
* `pytest.ini`: Конфигурационный файл для pytest.
* `requirements.txt`: Список зависимостей проекта.

## Установка и запуск
### Локальный запуск
   * __Требования__: перед запуском приложения убедитесь, что у вас установлены следующие компоненты:
      * Python 3.10+
      * PostgreSQL
      * Redis

   1. __Клонирование репозитория__:
      
      ```bash
       git clone https://github.com/Keka17/Task-Manager.git
       ```
  2.  __Переход в директорию проекта__:

       ```bash
       cd Task-Manager
      ```
   
3. __Создание и активация виртуальной среды__:
   
   ```bash
      python3 -m venv venv

      venv\Scripts\activate (Windows)

      source venv/bin/activate (MacOS, Linux)
   ```
  
4. __Установка зависимостей__:
   
    ```bash
      pip install -r requirements.txt
    ```
5. __Настройка переменных окружения__:
   
Cоздайте файл `.env` в корне проекта, заполнив его в соответствии с файлом `.env.example`. Параметры `COMPANY_DOMAIN`, `POSITIONS` _необязательны_.

6. __Настройка файлов локализации__:

   Чтобы переводы отобразились в приложении, из корневой папки выполните команду компиляции переводов:
   
   ```bash
    pybabel compile -d app/locales -D messages
    ```
   
7. __Запуск приложения__:
   
   Для полноценной работы нужно запустить три компонента:
     * __API сервер__: из корневой папки
    
    ```bash
    uvicorn app.main:app --reload
    ```
     * __Celery Worker__:
    
    ```bash
    celery -A app.tasks.celery_app.celery_app worker --loglevel=info
    ```
     * __Celery Beat__:
    
    ```bash
    celery -A app.tasks.celery_app.celery_app beat --loglevel=info
    ```

### Запуск через Docker

__Примечание__: этот способ запуска __быстрее__, т.к. не требует отдельной установки PostgreSQL и Redis. Убедитесь, что у вас установлен __Docker__ и __Docker Compose__.

1. __Клонирование репозитория__:
      
       git clone https://github.com/Keka17/Task-Manager.git
  2.  __Переход в директорию проекта__:

       ```bash
       cd Task-Manager
      ```

3. __Настройка переменных окружения__:
   
Cоздайте файл `.env.docker` в корне проекта, заполнив его в соответствии с файлом `.env.example`. Параметры `COMPANY_DOMAIN`, `POSITIONS` _необязательны_.

4. __Сборка и запуск__:
   
   ```bash
    docker-compose --env-file .env.docker up --build
    ```

### Доступ к приложению
* После успешного запуска API будет доступно по адресу: http://localhost:8000/.
* После запуска сервера доступна __интерактивная user-friendly документация__ с детальным описанием эндпоинтов и возможностью проверить функционал:
   * __Swagger__: http://localhost:8000/docs
   * __Redoc__: http://localhost:8000/redoc

#### Примечания: 
* Интеграция с почтовым сервисом требует инициализации SMTP-клиента. Учетные данные (`MAIL_USERNAME, MAIL_PASSWORD, MAIL_FROM`) добавляются в файлы окружения. Порт (`MAIL_PORT`) и хост сервера (`MAIL_SERVER`) должны быть вынесены в `config.py`.
* По умолчанию отправка email настроена на русский язык. Если вам необходим английский: в файле с фоновыми задачами `app/tasks/notification_email.py`) в функциих `uncompleted_task_email` и `delayed_task_email` закомментируйте блок для __ru__ и раскомментируйте для __en__.

## Эндпоинты
* ### __Users__
  * `POST /users/signup`: Регистрация нового пользователя.
  * `GET /users/signup_confirm`: Подтверждение регистрации через ссылку.
  * `GET /users/`: Получение списка всех пользователей (protected).
  * `GET /users/me`: Получение информации о текущем пользователе.
  * `GET /users/{user_id}`: Получение информации о конкретном пользователе (protected) по его id.
  * `DELETE /users/{user_id}`: Удаление конкретного пользователя (protected), доступно только администратору (поле `is_superuser` в БД).

* ### __Authentication__
   * `POST /auth/login`: Аутентификация для получения пары токенов.
   * `POST /auth/refresh`: Обновление пары токенов. В заголовках обязательно указывать refresh-token (`x-refresh-token`).
   * `POST /auth/logout`: Выход из системы. В заголовках обязательно указывать refresh-token (`x-refresh-token`).
     
* ### __Tasks__
  * `POST /tasks/`: Создание новой задачи (protected).
  * `GET /tasks/`: Получения списка всех задач (protected). Возможные параметры запроса: level, completed.
  * `GET /tasks/{task_id}`: Получение конкретной задачи (protected).
  * `GET /tasks/my_tasks`: Получение списка задач текущего пользователя (protected). 
  * `PATCH /tasks/{task_id}`: Обновление поля `content`. Действие доступно только автору задачи (protected).
  * `PATCH /tasks/complete/{task_id}`: Завершение задачи путем добавления временной метки в поле `completed_at`. Эндпоинт доступен только автору задачи (protected).
  * `PATCH /tasks/remark/{task_id}`: Добавление ремарки к задаче (protected). Действие доступно только администратору.
  * `DELETE /tasks/{task_id}`: Удаление конкретной задачи (protected). Действие доступно только автору задачи и администратору.

* ### __Frontend__
  * `GET /`: Отображение лендинговой страницы (landing page).
  * `GET /auth/login-page`: Отображение HTML-страницы входа.
  * `GET /tasks/board/`: Получение списка всех незавершенных задач для доски.
  * `GET /tasks/board/{task_id}`: Получение конкретной задачи.
  * `GET /ws/enter`: Доска с задачами (protected).

#### Почтовые уведомления (FastAPI-Mail + Celery)
Рассылка реализована через __BackgroundTasks__, что гарантирует мгновенный отклик API — пользователю не нужно ждать завершения сетевого запроса к почтовому серверу.

Система автоматически информирует сотрудников о важных событиях (примеры с локализацией):
* __Напоминания__: При создании задачи уровня __A__ сотрудник сотрудник получает напоминание каждые два часа, пока задача не будет выполнена.

### Процесс верификации email
1. __Генерация токена__: После регистрации формируется уникальный URL-safe токен (библиотека __ItsDangerous__), который гарантирует криптографическую целостность ссылки и защиту от подделки данных.
2. __Отправка уведомления__: На указанную почту отправляется письмо с ссылкой для активации профиля (локализация).

<img width="714" height="716" alt="email_confirmation" src="https://github.com/user-attachments/assets/c71c4281-fae3-4d90-8edf-eb93989fc2f9" />

3. Варианты событий:
  * __Успешная активация__: Если в течение 10 минут (время жизни токена) пользователь переходит по ссылке, полю `is_verified` таблицы `users` присваивается значение True. Пользователь получает полный доступ к функционалу приложения.

<img width="1158" height="624" alt="email_confirmed" src="https://github.com/user-attachments/assets/d2f46f6d-e518-4498-9a03-e4c28807fb33" />

  * __Истечение времени__: По истечении 10 минут токен становится невалидным. При попытке перейти по ссылке отображается страница с уведомлением об ошибке, неверифицированного пользователя удалят из БД фоновой задачей Celery.

### Гибкая настройка под компанию

Приложение поддерживает кастомизацию под корпоративные стандарты через переменные окружения:
* __Корпоративный домен (`COMPANY_DOMAIN`)__: Если указан, то регистрация доступна только для сотрудников с почтой на этом домене.
* __Список должностей (`POSITIONS`)__: Строгий списка ролей, доступных при создании профиля сотрудника.
* __Рабочее время (`LAST_HOUR`)__: Определяет последний рабочий час (по умолчанию 19:00), который будет считаться дедлайном срочных задач.
* __Часовой пояс (`TZ_IANA`)__: Используется для корректной отправки уведомлений и расчета дедлайнов (по стандарту Time Zone Database; напр., "Europe/Moscow").
* __Email Администратора (`ADMIN_EMAIL`)__: Указываемый в письмах адрес для обратной связи.
